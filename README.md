# Notary Record-Keeping Dashboard

Backend and repository layout for the record-keeping dashboard at
**https://notary.wes-griffin.com**, built on Wix Velo with Wix Git Integration.

Three CMS collections, one hooks file, one web-module the pages call, and a
nightly job. The visual dashboard is built in the Wix Editor; this repo owns
the data model and every rule that protects it.

## Repository layout

```
.
├── src/
│   ├── backend/
│   │   ├── data.js                 # Wix Data hooks (validation, immutability, status flow)
│   │   ├── dashboard.web.js        # Web methods called from page code
│   │   ├── collections.web.js      # Admin-only: create the collections from schemas/
│   │   ├── jobs.config             # Scheduled jobs
│   │   ├── jobs/credentialExpiry.js
│   │   ├── lib/validators.js       # Field validators + ValidationError
│   │   ├── lib/credentials.js      # Credential array normalization + derived fields
│   │   └── schemas/                # One file per collection = source of truth
│   │       ├── UserProfile.js
│   │       ├── TransactionLog.js
│   │       ├── DocumentStatus.js
│   │       └── index.js
│   ├── public/constants.js         # Enums shared by backend AND page code
│   ├── pages/masterPage.js         # Site-wide code (dashboard login guard)
│   └── styles/global.css
├── docs/
│   ├── WIX_GIT_INTEGRATION.md      # Connect this repo to the Wix site
│   ├── DOMAIN_SETUP.md             # Point notary.wes-griffin.com at the site
│   └── PAGE_CODE_EXAMPLES.md       # How the dashboard page calls the backend
├── wix.config.json                 # Wix writes siteId here on first sync
├── jsconfig.json                   # Path aliases: backend/*, public/*
├── package.json                    # @wix/cli
└── .eslintrc.json
```

Page code files (`src/pages/<Name>.<id>.js`) are generated by Wix when you add
pages in the Editor; they are intentionally not pre-created here.

## Data model

All three collections use member ownership: the `_owner` system field is the
site member who created the row, and collection permissions are
**Site Member Author** for read/update, so a member only sees their own rows.

### `UserProfile` — one row per member

| Field | Type | Notes |
| --- | --- | --- |
| `displayName`, `businessName`, `email`, `phone` | Text | |
| `commissionState`, `commissionNumber` | Text | |
| `credentials` | Array | Objects: `{ id, type, label, fileUrl, fileName, uploadedAt, expiresAt }` |
| `nextCredentialExpiry` | Date & Time | **Derived** by hooks |
| `credentialStatus` | Text | **Derived**: `none` / `valid` / `expiring` / `expired` |

Credential files are uploaded to Wix Media with an Upload Button; only the
returned URL and metadata are stored here.

### `TransactionLog` — append-only journal

| Field | Type | Notes |
| --- | --- | --- |
| `entryNumber` | Number | Per-member sequence, assigned by hook |
| `actDate` | Date & Time | Required, cannot be in the future |
| `actType` | Text | One of `ACT_TYPES` in `public/constants.js` |
| `clientName`, `clientAddress` | Text | Required |
| `clientEmail`, `clientPhone` | Text | Editable after insert |
| `idMethod` | Text | One of `ID_METHODS` |
| `fee` | Number | ≥ 0, rounded to cents |
| `documentDescription` | Text | |
| `notes` | Text | Editable after insert |
| `voided`, `voidReason` | Boolean, Text | Corrections are voids, never deletes |

After insert, every field except notes, contact details, and void flags is
locked by the `beforeUpdate` hook. Delete is admin-only.

### `DocumentStatus` — Draft → Pending Signature → Completed

| Field | Type | Notes |
| --- | --- | --- |
| `title` | Text | Required |
| `status` | Text | `Draft` / `Pending Signature` / `Completed` |
| `transaction` | Reference → `TransactionLog` | Optional; must belong to the same member |
| `fileUrl`, `fileName`, `clientName`, `notes` | URL / Text | |
| `statusHistory` | Array | **Derived**: `[{ status, at, by }]` |
| `lastStatusChange`, `completedAt` | Date & Time | **Derived** |

Allowed transitions live in `DOC_STATUS_TRANSITIONS`. `Completed` is terminal
for members (no edits, no reopen, no delete); a site owner can override.

## Hooks at a glance (`src/backend/data.js`)

| Collection | beforeInsert | beforeUpdate | beforeRemove |
| --- | --- | --- | --- |
| UserProfile | one profile per member; normalize credentials; derive expiry fields | lock `_owner`; re-derive | owner only |
| TransactionLog | validate all fields; assign `entryNumber` | lock immutable fields; void is one-way with reason | owner only |
| DocumentStatus | default `Draft`; verify linked transaction ownership; seed history | enforce transitions; append history; freeze Completed | block delete of Completed |

`onFailure` hooks log non-validation errors to Site Monitoring.

## Setup

1. **Connect the repo** — follow [docs/WIX_GIT_INTEGRATION.md](docs/WIX_GIT_INTEGRATION.md).
2. **Install locally** — `npm install` (runs `wix sync-types`), then `npm run dev`.
3. **Create the collections** — either call `provisionCollections()` from
   `backend/collections.web.js` once as an admin, or create them by hand in
   CMS using the exact keys/types in `src/backend/schemas/`.
4. **Enable members** — add the Wix Members Area app so notaries can log in.
5. **Build the dashboard page** in the Editor and wire it using
   [docs/PAGE_CODE_EXAMPLES.md](docs/PAGE_CODE_EXAMPLES.md).
6. **Connect the domain** — follow [docs/DOMAIN_SETUP.md](docs/DOMAIN_SETUP.md).

## Conventions

- Every allowed value (act types, ID methods, statuses) lives in
  `src/public/constants.js` and nowhere else.
- Page code never writes derived fields; hooks own them.
- Backend web methods never pass `suppressAuth` on member-facing calls, so
  collection permissions stay the last line of defense.
- Secrets go in Wix Secrets Manager, never in this repo.
